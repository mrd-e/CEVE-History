# 0009：事实快照、人工判断与功能复审分别维护

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：人物身份、当前归属、历史参战、品评组件、复审指纹
- 关联：[统一标准](../repository-standards.md)、[增量复查](../review-workflow.md)、[开发边界](../development.md#展示组件与样例的执行边界)、[六维品评](../person-radar.md)

## 背景

同一人物会同时出现在列传、军团、战役和趣味组件中，但当前归属、战时归属、身份判断与主观品评不是同一类数据。把刷新、展示修订或代码校验等同于全量内容复审，会覆盖历史、重复维护人工判断，或把小任务扩大成全仓调查。

## 决策

- 抓取快照、人工身份与归方、趣味品评分别存储并通过已有模块读取。刷新只替换约定的抓取字段，不能覆盖人工身份、小号、分方或评分；能够从现有数据推导的结果不另建人工全员总表。
- 更新人物和军团的当前所属时同步受影响的当前展示；历史战役使用本场快照与组织映射，不以今天的联盟归属回填过去。小号确认和当前同团仍须按领域规则判断，不能由展示关联反推身份。
- 雷达与阵营分别在 `person.radar`、`person.alignment` 维护，作为独立展示组件。只改组件时不触发主列传的 `combat`、`writing-depth` 复审；同时实质补写正文时，正文仍按列传流程验收。
- 复审按功能记录结论、覆盖范围与失效依据。规则或实现指纹变化须按增量复查流程声明，不能为获得通过而扩大豁免、篡改已审状态或声称旧内容自动符合新规。
- 名称、统计与展示规则复用现有权威入口：例如游戏名校验走术语表与 `game-names`，活跃和特殊标记计算走 `activity`，不因同一事实出现在不同板块而各写算法。具体阈值与写作要求留在所属专题规则。

## 理由与取舍

将事实、判断和呈现分开，使刷新数据不会重写编辑结论，组件任务也能独立完成。功能指纹能定位哪些判断需要重看，但不能替代人工复审，也不能证明未覆盖的旧资料已经正确。

## 验收

- 相关入口：`scripts/character-snapshot.mjs`、`scripts/person-identity.mjs`、`scripts/battle-archive.mjs`、`scripts/activity.mjs`、`scripts/review.mjs` 及对应测试。
- 展示字段由 `review.mjs` 的 `PERSON_DISPLAY_FIELDS` 排除出主列传内容指纹；改正文仍能使对应复审失效。
- 涉及当前归属的修改定向核对关联展示和历史快照；涉及规则变更的修改报告实际复查范围，不顺带重评全员。
