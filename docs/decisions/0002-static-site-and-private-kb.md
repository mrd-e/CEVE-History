# 0002：公开静态站与私有资料库分离

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：站点构建、`kb/`、公开派生数据、`translator/`
- 关联：[开发与验证](../development.md#私有资料库-kb)、[网站设计](../site-design.md)、[统一标准](../repository-standards.md)

## 背景

公开正文需要稳定发布，取材档案、线索与复审登记需要独立保存。把两者混进同一构建，会让网站依赖私有资料与本机环境，也容易将原始材料公开。翻译框架同样有独立的版本与工作区。

## 决策

- 网站保持 Eleventy、Nunjucks、Markdown 与 Pagefind 的静态发布结构，部署到 GitHub Pages。浏览器不依赖本站数据库、后端或实时游戏数据查询；JavaScript 只做渐进增强。外部图片等既有例外以网站设计为准。
- 公开仓库保存正文、公开快照、网站资产和必要派生文件；私有资料在被忽略的独立仓库 `kb/`。正式构建与发布 CI 不读取 `kb/`。
- 私有路径由 `scripts/workspace.mjs` 统一识别和映射。工具继续使用逻辑路径，不各自硬编码物理位置；映射、目录清单和缺库行为按开发文档维护。
- 网站确需使用私有档案的汇总时，先用正式工具生成公开派生文件，再随公开仓库发布。例如 B 站展示读取 `src/_data/bilibili-public.json`，不在构建时打开原始档案。
- `translator/` 是独立翻译框架工作区，不属于网站源码或公开素材目录；其版本策略见 [ADR 0001](0001-translator-latest.md)。各仓库分别检查状态，提交授权不因目录嵌套自动扩散。

## 理由与取舍

公开站可以在没有私有库的环境中构建，私有资料也能独立维护。代价是公开派生文件需要显式更新，跨库改动需要分别核对。不得用把私有资料复制回公开目录的方式消除这一成本。

## 验收

- 路径映射与回流检查由 `scripts/workspace.test.mjs` 覆盖，公开索引不含私有路径。
- 涉及派生数据时核对生成器和公开文件；检查构建入口没有引入私有读取器。
- 缺少私有库的资料命令明确报错；不能把空结果报告为“没有资料”。网站构建的独立性在相关构建改动时验证，不为每次文档修订重建全站。
