# 0001：翻译框架跟随最新默认分支

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：`translator/`、天书自动收录、翻译回归 CI
- 关联：[自动收录](../news-automation.md)、[决策索引](README.md)

## 背景

翻译框架独立维护术语、检查器及复核流程，修正需要在后续收录中及时生效。固定旧版本会使站点继续运行已经修复的缺陷，增加无效重试和翻译成本。

## 决策

- 每次 CI 或自动收录运行都读取 `mrd-e/EVE-Online-Translation-Framework` 最新默认分支。`actions/checkout` 的该仓库条目不设置 `ref`，不得固定 commit、tag 或过时分支。
- 本地执行前核对框架版本；有未提交改动时保留，不通过重置覆盖。使用实际工作区内容进行验证。
- 日志与附件可以记录实际使用的 commit、工具及数据包指纹，用于诊断和判断任务是否兼容；这些记录不得反过来限制下一次 checkout 的版本。
- 框架变化时检查旧任务的兼容性，保留原任务。需要新建任务时输出原因；不得为复用旧成果而回退或固定框架。
- 私有框架的访问能力以实际授权和 checkout 结果为准，不能仅因 PR 来自 fork 就断言无法访问或省略真实框架回归。缺少授权时明确报告验证未完成，不以跳过充当通过。

## 理由与取舍

优先及时吸收翻译修正，接受默认分支更新可能改变行为的代价。通过真实框架离线回归、运行版本记录和任务兼容检查控制风险。固定 commit 虽有助于复现，但不能作为本仓库的常态运行策略。

## 验收

- 所有工作流中该框架的 checkout 都没有 `ref`；回归测试核对这一约束。
- 运行日志记录实际框架版本；测试和自动收录遵守同一读取策略。
- 操作文档不再要求读取“固定版本”的翻译框架。
