# 0011：收录失败计次封顶，维修代理可直接修复收录脚本

- 状态：已采纳
- 日期：2026-11-27（UTC）
- 范围：天书与正史自动收录的失败处理、维修代理、代理容器的命令隔离
- 关联：[Worker 触发与冷却](0005-worker-gated-news-automation.md)、[有限复核与恢复](0006-bounded-resumable-translation.md)、[共写与提交](0008-concurrent-git-writers.md)、[自动收录操作](../news-automation.md)、`scripts/ci-news/sync.py`

## 背景

单篇失败会留在待办里，Worker 每小时触发一次，同一个原因造成的失败每次都重付写稿额度，直到有人发现为止。环境缺陷在原样重试下永远不会好。例如代理镜像缺 socat，或者 Docker 默认安全配置拦住 bwrap，翻译代理的每条命令都会被拒。只判断“要不要重试”的代理也解决不了这类问题。

## 决策

- **失败计次**：额度冷却以外的失败都记入 `.github/news-state.json` 的 `failures`，包括调用失败、校验失败和非预期错误。键是待办键，内容有失败次数、维修次数、环境指纹、报错和维修结论。收录成功或正史记为已处理时清除该记录。额度冷却仍按 `modelRetryAfter` 处理，不计次。
- **维修代理**：模型能调通时，失败先交维修代理查因（opus、high、最多 60 轮）。
  - 次数上限：每轮最多维修一次；每篇在一次排队里最多维修 2 次。
  - 读写范围：代理在容器里只读整个仓库，`.git` 用空目录遮住，因为检出凭据存在 `.git/config`。可写的只有翻译任务目录和 `scripts/ci-news/`。
  - 结论三选一：
    - `fixed`：改了文件并修好。
    - `retry`：没改文件，是暂时故障。
    - `park`：只能由人处理，如工作流文件、令牌、翻译框架、上游原文。
- **脚本修复门槛**：`scripts/ci-news/` 的改动要同时满足三个条件才保留：结论为 `fixed`；不含符号链接；离线测试在无网络、无凭据的代理容器里通过。
  - 保留的改动并入本轮唯一一次提交，提交信息含“天书：自动修复收录脚本”，推送到 main 后从下一轮起生效。
  - 任一条件不满足，就撤回全部脚本改动，并记下未采纳的原因。
  - 工作流文件不在可写范围：Actions 令牌无权推送工作流。
- **搁置**：维修结论为 `park`，或累计失败 3 次仍未修好，就把该篇移出待办；正史条目同时记入已处理，Worker 不再为它触发。刚修好的再给一次机会，所以每篇在一次排队里至多尝试 5 次。
- **重新排队**：scan 时出现以下任一情况，搁置的待办重新排队，次数清零：
  - 运行环境指纹与搁置时不同，且当前环境不是维修代理自己改出来的。指纹涵盖翻译框架兼容指纹、收录脚本、代理镜像和工作流。
  - 天书原文更新，重新被发现。
  - 手动运行工作流时勾选 `requeue_parked`，全部搁置项重新排队。更换令牌这类指纹看不出的修复用这个办法。
- **命令隔离自检**：要执行命令的翻译代理，调用模型前先在容器里试一次 bwrap 隔离，这一步不花额度。起不来就按环境故障交给维修代理，不发写稿调用。
  - 代理容器放开 Docker 默认的 seccomp、AppArmor 和 /proc 遮蔽。运行器关闭 Ubuntu 对非特权用户命名空间的限制。
  - 容器仍然只读、以非 root 运行，保留 `CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=1`，凭据不进入代理执行的命令。

## 理由与取舍

- 额度花费有上限：每篇每次排队最多尝试 5 次、维修 2 次；每轮最多维修一次，同一原因拖垮的其他待办等修复上线后再重试。
- 修复必须能改文件才有意义。代价是未经人工审阅的脚本会带着令牌运行。约束手段有四项：离线测试门槛、限定可写范围、遮住 `.git` 凭据、不许改工作流。但测试只能证明既有行为没坏，不能证明改动无害。
- 不采用的方案：
  - 不限次数地每小时重试：浪费额度。
  - 关闭命令隔离让代理命令能跑：凭据会进入代理命令的环境。
  - 维修代理只给重试建议：解决不了环境缺陷。

## 验收

- `scripts/ci-news/test_repair.py` 覆盖以下行为：
  - 计次封顶与搁置；搁置的正史退出订阅发现。
  - 重新排队的三种情况：环境变化、手动勾选、原文更新；维修代理自改的环境不解除搁置；过时记录清理。
  - 通过测试的修复随本轮提交；测试不通过或结论不符时撤回；含符号链接时撤回。
  - `park` 结论立即搁置；维修次数上限；模型调用故障不请维修代理。
  - 维修工作区遮住 `.git`；命令隔离试运行失败时不调用模型。
- 线上每次失败都在步骤摘要里写明：第几次失败、原因、处理、未采纳的修复和报错原文。搁置后，Worker 的整点检查不再为该篇触发运行。
