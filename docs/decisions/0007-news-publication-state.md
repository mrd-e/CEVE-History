# 0007：页面与订阅状态共同落盘，补丁按真实快照增量更新

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：人工与自动收录、补丁合辑、订阅状态、失败回滚
- 关联：[自动收录操作](../news-automation.md#人工与自动收录的状态)、[翻译恢复](0006-bounded-resumable-translation.md)、[并行写入](0008-concurrent-git-writers.md)

## 背景

页面已经完成而待办仍未清除，会让下一次扫描重复处理。补丁合辑同时包含旧章节、新章节和会变化的前言；只登记整篇更新时间，无法安全复用旧译文。用最新原文为旧译文补指纹，还会把没有翻译过的变化误标成完成。

## 决策

- 人工命令与自动收录共用状态计算，不各自修改 `.github/news-state.json` 的完成语义。成功收录同时登记已收录短名、移除本篇待办、记录章节指纹，并在页面变化时标记待部署。
- 页面校验和状态计算先通过再落盘；状态写入失败时还原本次页面，自动收录的后续单篇检查失败时还原本次页面与状态。这里的共同落盘是异常恢复约束，不宣称两个文件具有数据库事务或断电原子性。
- 合辑补丁保持同一页面，按日期和当日序号拆节；前言也有独立指纹。只处理新增或实际变化的部分，保留未变化的已发布译文，不能因一次更新整篇重译。
- 指纹必须对应实际用于翻译的英文快照。已有页面缺少任何已发布章节的原文指纹时，在模型调用前停止，列出缺项并保留待办；不得静默重译全部旧节或拿当前官网冒充发布当时的快照。
- 人工补丁收录提供完整来源快照，或使用任务旁实际保存的 `source.md`；已直接编辑页面时通过 `news record` 补登记。具体参数按操作文档，不靠手动清空待办代替收录登记。
- 英文变化但官译未更新时，不以仍能访问中文版为由复用旧译文。页面写入前重新核对并行修改；发生冲突保留人工稿和已完成翻译任务，不覆盖后再回滚到过时版本。
- 翻译完成、页面及状态落盘、Git 推送、部署请求和网站上线是不同阶段。推送或部署失败可以复用成稿重试，不能回到模型写稿阶段。

## 理由与取舍

将完成状态绑定到实际稿件和来源，可以同时支持人工修订与自动增量更新。代价是旧合辑缺少来源基线时必须先补齐，不能用无依据的指纹换取暂时运行成功。

## 验收

- 共享实现入口：`scripts/news-publication.mjs`、`scripts/ci-news/publication.py`、`scripts/news-workbench.mjs` 与自动收录的 `patch_translation`、`publish`。
- `scripts/news-publication.test.mjs` 和 Python 收录测试覆盖状态写入失败、日期不一致、指纹不符、缺旧节基线、单节变化、并行编辑，以及提交成功但推送失败后的恢复。
- “缺基线”用例须证明没有发生模型调用；成功用例须同时核对页面、待办和章节指纹，不能只检查译文文件存在。
