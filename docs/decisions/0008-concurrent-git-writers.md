# 0008：人工与自动化共写时保留各仓库和远端成果

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：公开库、私有库、翻译框架、自动收录提交与推送
- 关联：[全仓授权边界](../../AGENTS.md)、[开发与验证](../development.md)、[公开与私有库](0002-static-site-and-private-kb.md)

## 背景

新闻自动化会直接向 main 写入订阅状态和文章；人工修订也可能同时进行。本地工作区干净或推送命令成功，都不能证明远端没有新增成果。嵌套目录下的独立仓库也各有自己的索引和历史。

## 决策

- 修改、修复和 ADR 整理不自动授权提交、推送或改写历史；遵守全仓授权边界。授权的路径、仓库和操作分别判断，不能把一次操作授权变成后续任务的默认权限。
- 保留其他任务的暂存、未暂存和未跟踪内容。跨独立仓库迁移时按实际差异合并，并在目标重新生成派生文件，不能整文件覆盖另一边的不同修改。
- 新闻自动化按明确文件列表提交，正常推送到 main；不为绕过分支规则改为强推。分支策略须与自动写入方式相容，拒绝时报告失败并保留待办与成果。
- 每轮自动收录只在收尾提交一次：订阅状态、成稿页面、折扣清单和部署标记同一提交，推送后再请求部署；只有部署请求失败才另记一个待重试提交。收录开始后由收录自己提交，不另把未带页面的状态单独推上去。
- 人工操作与自动收录同属并发写入。改写历史前即使已有明确授权，也须读取最新远端并核对差异，保留机器人或其他会话的新提交与内容；不能把机器人状态提交视为可随意丢弃的噪声。
- 需要强推时采用针对已核对远端提交的 lease；lease 只防检查后的竞争，不能替代检查前已经存在的远端独有提交。不能把“强推成功”当成“没有覆盖他人工作”。
- 提交与推送失败不清除翻译任务；恢复时重新核对远端和当前文件。公开库、`kb/`、`translator/` 分别报告结果。

## 理由与取舍

保留现有自动直接发布方式，同时把所有写入者视为真实并发参与者。接受偶发推送冲突和重新整合的成本，避免以线性历史或操作成功为代价丢失订阅状态。

## 验收

- 收录提交核对 `commit` 的显式路径、`save` 的单次提交与推送后部署顺序，以及失败保留行为；不改用全索引提交或强推。
- 获授权执行 Git 操作时，分别检查目标仓库的工作区、索引及最新远端差异，操作后核对目标文件和远端结果。
- 本记录是操作约束，不代表已有全自动防覆盖机制；文档任务不通过真实改写或推送来测试它。
