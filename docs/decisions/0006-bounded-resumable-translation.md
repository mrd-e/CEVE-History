# 0006：翻译有限复核，按持久化阶段恢复

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：新闻自动翻译、官方译文校订、模型调用、翻译任务附件
- 关联：[框架版本](0001-translator-latest.md)、[自动收录操作](../news-automation.md)、[页面与状态](0007-news-publication-state.md)

## 背景

复核意见、脚本检查错误和服务调用失败是不同问题。把它们统一成“整篇失败后重跑”，会重复写稿和复核，已经完成的补丁章节也会重新消耗额度。有限复核后仍存在的措辞分歧，不应成为永久待办。

## 决策

- 收录宿主调用独立翻译框架的准备、检查、送审和渲染协议，不在站点另建一套翻译规则。自动化中的写稿、独立复核、修订及官译校订统一使用 Claude Code 的 `opus`、`high`；这不改变交互式会话的模型选择。
- 写稿与复核使用独立上下文。复核最多两轮，不为第二轮保留意见启动第三轮或重新开整篇翻译。通过脚本检查并完成两轮流程后，分歧随交付说明和报告保留，按框架的“复核后修订”结果发布。
- 脚本检查仍是发布门槛。修订无法产出合法稿时，使用框架允许的已通过检查的送审稿及意见登记流程，不把检查失败的修订稿发出，也不伪造通过状态。
- 格式与登记错误只允许一次针对性修正；网络、认证和额度故障不进入 JSON 修正循环。额度耗尽立即停止本轮后续模型调用，记录恢复时间，在冷却结束前不再送译。
- `translator/jobs/` 的任务状态是恢复断点。来源和工具、技能、数据包兼容时，从未完成阶段继续，保留已写稿块和已完成章节；已完成任务只校验和装配，不再调用模型。
- 成果、报告和调用诊断通过累计附件保存，成功、失败和正常取消均尝试保存。恢复以完整任务快照择优，不能拼接不同轮次的状态、草稿和报告；框架更新不兼容时保留旧任务并说明新建原因，不能回退框架来迁就缓存。

## 理由与取舍

用结构校验保证可发布，用有限独立复核控制翻译质量，用持久化断点限制重复成本。保留分歧意味着交付不宣称译文没有争议；附件也不是永久存储，过期或运行器被强制终止时可能丢失最后阶段。

## 验收

- `scripts/ci-news/test_sync.py` 与 `scripts/ci-news/test_recovery.py` 使用真实框架、模拟模型验证协议；不为离线回归消费订阅额度。
- 覆盖第二轮仍有意见、修订检查失败、服务故障、额度冷却，以及写稿／复核／修订中断后恢复。已完成任务重跑应没有模型调用，补丁后节失败不应丢失前节成果。
- `publication-report.json`、复核报告和调用日志保留未解决意见；工作流附件保存使用 `always()`。保留期与恢复命令只在操作文档维护。
