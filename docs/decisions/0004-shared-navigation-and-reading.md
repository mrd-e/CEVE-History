# 0004：导航与长文能力共用实现，返回链接直达目录

- 状态：已采纳
- 日期：2026-11-25（UTC）
- 范围：详情页返回、导航、目录列表、长文呈现、主题样式
- 关联：[网站设计](../site-design.md)、[长文排版](../article-layout.md)、[模板指令](../../src/_includes/AGENTS.md)

## 背景

同一阅读能力分散在各板块后，容易出现一处修复、其他页面继续出错。返回链接若改成浏览器后退，其结果还会受搜索入口、外站来源和连续翻页影响，违背“返回目录”的含义。

## 决策

- 详情页返回统一使用 `src/_includes/back.njk`，由调用方明确传入目录地址；链接经过部署子路径处理。不得依据 referrer、历史长度或前一页改调 `history.back()`。
- 保留原生链接行为，包括无 JavaScript、修饰键和新标签页打开。连续阅读后的“上一篇／下一篇”与“返回目录”是不同操作。
- 板块导航从统一登记生成；长文预处理走 `scripts/article-prose.mjs`，目录、折叠和分页增强复用 `src/assets/js/article-ui.js`。目录基础交互优先复用现有 `src/assets/js/directory-utils.js`，板块特有筛选仍由各自模块负责。
- 共用组件修复要核对全部调用方。共用实现不要求所有板块采用相同卡片、筛选默认值或正文结构；视觉与交互差异以网站设计为准。
- 全站主题色与阅读排版在共享样式中维护，避免逐页复制补丁。正文段落采用左对齐，避免中西文混排被两端对齐拉散；表格在自身容器内处理宽度与滚动，不能撑开整页。具体尺寸不在 ADR 另存一份。

## 理由与取舍

明确目录地址让返回行为可预测，共用基础能力使修复覆盖所有板块。保留板块适配层，避免为了抽象而强行统一已有的不同交互。

## 验收

- `scripts/navigation.test.mjs` 覆盖实际调用组件的列传、战役、军团、天书、正史和术语表，含不同进入来源、修饰键与部署子路径。
- 长文能力使用 `scripts/article-prose.test.mjs`；涉及浏览器增强时按网站设计检查受影响页面的深浅主题、宽窄屏与无 JavaScript 行为。
- 不以只检查被报告的一页代替共享逻辑的调用方检查，也不为独立样式修复扩大成全篇内容复审。
