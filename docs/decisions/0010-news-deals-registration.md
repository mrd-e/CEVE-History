# 0010：收录天书时判断折扣增补，与页面同一提交

- 状态：已采纳
- 日期：2026-11-26（UTC）
- 范围：天书自动收录、人工收录第 4 步、折扣清单 `src/news/calendar.json`
- 关联：[0003](0003-official-sections-and-deals.md)、[0005](0005-worker-gated-news-automation.md)、[0007](0007-news-publication-state.md)；[天书指令](../../src/news/AGENTS.md)的折扣板块；`scripts/news-calendar.mjs`、`scripts/news-workbench.mjs`、`scripts/ci-news/sync.py`

## 背景

自动收录只写天书页面，官方促销公告带来的折扣与赠送要另行手工登记，`/deals/` 因此滞后。资料片上线、周年庆等非促销分类的公告也常带商城折扣，只看“促销”分类会漏登。

## 决策

- 普通新闻写入并通过单篇校验后，由 `npm run news -- deals <链接>` 预判要不要请模型判断：已有条目指向本篇、列在 `skip`、补丁说明、早于清单起点的不判；促销分类必判；其他分类在标题或正文出现商城、PLEX、欧米伽、多人物训练、礼包、折扣等字眼时才判。
- 判断材料由工具生成，规则直接取天书指令的折扣板块原文，不另写一份；另附优惠类型、前后 60 天的已有条目和中英文正文。模型只交 `{ entries, link }`：`entries` 为新增条目，不写 `news`；`link` 把本篇挂到已有条目，可指定本篇为正式公告，只许补改 `nameEn`、`off`、`end`、`channel`、`discount`、`bonus`。
- 工具填 `news`、按开始时间与键插入、固定字段顺序，整份清单通过 `validateCalendar` 才写入；不合格时带报错修正一次。
- 促销公告判断为空时，工具把短名记入清单顶层 `skip`；涂装、SKINR 等不收的促销只判断一次，`news:check` 也不再提示未登记。非促销公告判断为空不记，免得名单膨胀。
- 清单改动与页面放进同一个“天书：收录”提交，一起标记部署。判断失败或额度不足时还原页面、订阅状态与清单，本篇留在待办；通过的判断按材料指纹缓存，重试不重复调用模型。

## 理由与取舍

- 规则只维护一处，天书指令改了折扣规则，自动判断随之生效。
- 模型不碰文件，只交结构化结果，宿主校验后落盘，与翻译、校订沿用同一模式。
- 非促销公告靠字眼预判，以少量多余的模型调用换取不漏登；每篇最多多一次调用。
- 不收的促销不用关键词预先排除：标题带“涂装／SKIN”的促销公告多数另有 PLEX、欧米伽折扣或礼包，按字眼跳过会漏登；改为记下模型的判断结果。
- 不采用“页面先发、折扣后补”：那样要新增状态字段和第二条提交路径，且会出现页面已上线、清单未登记的中间态。代价是折扣判断失败会推迟整篇上线。

## 验收

- `scripts/news-calendar.test.mjs` 覆盖预判、同期条目、规则摘取、并入校验（插入顺序、关联、限改字段与拒收）和 `skip` 的写入、跳过、移出与校验。
- `scripts/ci-news/test_recovery.py` 覆盖清单与页面同一提交、判断失败与额度不足时整篇回滚、修正一次与缓存复用。
